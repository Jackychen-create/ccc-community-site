# 部署與設定

第一次架站、換帳號、加管理員時照這份做。日常發新版本看 [發布流程](發布流程.md)。

## 1. Supabase

1. 到 supabase.com 建立專案。
2. 打開 **SQL Editor**，把 `supabase/schema.sql` 整份貼上執行。
3. 打開 **Authentication → Sign In / Providers**，照下面設定：
   - **Allow new users to sign up：關閉**。這一步一定要做，不然別人可以不用實驗室密碼直接註冊。
   - **Confirm email：保持開啟**
   - **Secure email change：保持開啟**
4. 建立你自己的管理員帳號：**Authentication → Users → Add user → Create new user**
   - Email 填你的 Gmail（`a0926580734@gmail.com`）
   - 設一組密碼，並勾選 **Auto Confirm User**
   - 管理員帳號只能在這裡建立，不能用實驗室密碼加入。
5. 打開 **Project Settings → API**，記下這三個值：Project URL、anon public key、service_role key。
6. 把 `public/config.js` 裡的 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY` 換成你的。這兩個值本來就是公開的，可以放在前端。

## 2. Cloudflare R2

1. 打開 **R2 → Create bucket**，名稱例如 `community-videos`。不要開啟 Public access。
2. 打開 **R2 → Manage API Tokens → Create API token**：
   - 權限選 **Object Read & Write**，範圍只限這個 bucket。
   - 記下 Access Key ID、Secret Access Key，以及頁面上的 Account ID。
3. 打開 bucket 的 **Settings → CORS Policy**，貼上下面這段（把網址換成你的 pages.dev 網址；搬家期間可以新舊網址都放），後台才能直接在網頁上傳：

```json
[
  {
    "AllowedOrigins": ["https://你的網站.pages.dev"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["content-type", "content-length", "range"],
    "ExposeHeaders": ["etag", "content-length", "content-range"],
    "MaxAgeSeconds": 3600
  }
]
```

之後如果綁了自己的網域，記得把網域加進 `AllowedOrigins`。

## 3. Cloudflare Pages

1. 把這個資料夾推到 GitHub（建議 private）。
2. Cloudflare 後台 → **Workers & Pages → Create → Pages → Connect to Git**，選這個 repo。
3. 建置設定：
   - **Framework preset**：None
   - **Build command**：`npm install`
   - **Build output directory**：`public`
4. **Environment variables**（Production）填入下面這些值，金鑰類請選 **Encrypt**（範本在 `.dev.vars.example`）：

| 名稱 | 內容 |
|---|---|
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role 金鑰，**絕對不要放到前端或 GitHub** |
| `R2_ACCOUNT_ID` | Cloudflare Account ID |
| `R2_ACCESS_KEY_ID` | R2 token 的 Access Key ID |
| `R2_SECRET_ACCESS_KEY` | R2 token 的 Secret |
| `R2_BUCKET` | bucket 名稱 |
| `ADMIN_EMAILS` | 可以進後台的 Email，多人用逗號分隔，例如 `a0926580734@gmail.com` |

5. 按 **Save and Deploy**。之後每次推到 GitHub 都會自動重新部署；改了環境變數要到 **Deployments → 最新一筆 → Retry deployment** 才會生效。
6. 拿到 `xxx.pages.dev` 網址後，把它加進 R2 bucket 的 CORS `AllowedOrigins`（第二節）。

## 4. 第一次使用

1. 打開 `你的網址/admin`，用第四步建立的 Gmail 帳號登入。
2. 到 **實驗室密碼** 產生一組（例如可以用 30 次），按「複製加入訊息」貼給研究員。研究員點開連結，實驗室密碼會自動帶入。
3. 到 **影片** 把直播錄影拖進去。系統會自動抓片長和封面，上傳完補上標題、簡介、教材，就可以發布。

### 想讓別人也能進後台
1. 把他的 Email 加進 Cloudflare Pages 的 `ADMIN_EMAILS`，然後重新部署。
2. 在 Supabase 的 Users 用 **Add user**（勾 Auto Confirm）幫他建立帳號。

管理員分兩種（規則在 `public/assets/js/shared/roles.js`）：
- **主要管理員**（預設）：全部功能。
- **協作管理員**：只能管影片（上傳、編輯、發布、寄信通知）、排直播預告、看和回覆提問、看觀看統計、看研究員名單（不能停權、重設密碼、改資格）。實驗室密碼、交易量、待跟進、網站狀況、Discord 都看不到，伺服器也會擋。

要把某位管理員設成協作管理員：Supabase → SQL Editor 執行（Email 換成他的，多位就多列幾個）：
```sql
insert into public.settings (key, value) values ('admin_roles', '{"oc@example.com": "editor"}')
on conflict (key) do update set value = excluded.value;
```
改回主要管理員：把他從這個清單拿掉再執行一次。

用實驗室密碼加入的研究員帳號，就算 Email 後來被加進管理員名單，也不會變成管理員。這是刻意的設計，因為研究員註冊時沒有驗證過信箱。

## 5. 寄信通知（選用）

發布新影片時可以寄信通知研究員。用 Brevo 寄信，免費方案每天 300 封，夠 20–30 位研究員用。

1. 到 brevo.com 註冊。
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender**，寄件人填你的 Gmail，收信完成驗證。
3. **SMTP & API → API Keys → Generate a new API key**，複製金鑰。
4. Cloudflare Pages 加三個環境變數，然後重新部署：
   - `BREVO_API_KEY`：剛剛的金鑰（選 Secret）
   - `MAIL_FROM`：第 2 步驗證過的 Email
   - `MAIL_FROM_NAME`：`CCC 交易實驗室`

沒設定也沒關係，後台按「寄信通知」時會提示還沒設定，其他功能照常。用 Gmail 當寄件人，信有可能被分到垃圾信，第一次請研究員把它標成「不是垃圾郵件」。之後如果有自己的網域，改用網域信箱寄會更穩。

## 6. Bybit、BingX 自動抓交易量（選用）

研究員綁定 Bybit、BingX 的 UID 後，網站每天自動抓交易量。哪一間沒設定，研究員就看不到那一間的「綁定」按鈕，其他功能照常。

1. 建立唯讀的 API Key：
   - **Bybit**：用 CCC 的 **Bybit 聯盟（Affiliate）帳號** → API 管理 → 新增，權限**只勾「代理商」（Affiliate）**，其他全部不要勾。IP 白名單先不設。
     - 沒設 IP 白名單的 Key，Bybit 可能給有效期限（例如 3 個月）。建好後在 Bybit 後台看一下到期日，記在行事曆，到期前換新的。
   - **BingX**：用 CCC 的 **BingX 代理商帳號** → API 管理 → 建立，**只勾「唯讀」**。IP 白名單先不設（Cloudflare 的出口 IP 不固定）。
2. Cloudflare Pages → Settings → **Environment variables**（Production），都選 **Encrypt**：
   - `BYBIT_API_KEY`、`BYBIT_SECRET_KEY`
   - `BINGX_API_KEY`、`BINGX_SECRET_KEY`
   - `CRON_SECRET`：自己產生一串很長的亂碼（例如密碼產生器 40 個字），每天自動同步用來證明「是我們自己在呼叫」
3. **Deployments → 最新一筆 → Retry deployment**，讓設定生效。
4. 每天的排程（Supabase，東京）：Supabase → **SQL Editor**，貼上下面這行，把中間換成第 2 步的 `CRON_SECRET`，按 Run：
   ```sql
   select vault.create_secret('這裡貼 CRON_SECRET', 'cron_secret');
   ```
   之後每天台灣時間 10:17、18:17 會自動同步。排程本身已經建好（`supabase/schema.sql` v1.9，v1.16.2 改成一天兩次），沒放密碼之前它什麼都不做。要換密碼：`select vault.update_secret((select id from vault.secrets where name = 'cron_secret'), '新的密碼');`，Cloudflare 那邊也要一起改。
   - 為什麼不用 GitHub Actions：GitHub 的主機在美國，Bybit 會擋美國的連線。
5. 到後台「交易量」按 **立即同步** 試一次；兩間都顯示「上次同步 剛剛」就完成了。隔天早上再看一次，確認排程有跑。
6. （選用）想讓研究員在綁定視窗直接看到邀請連結，把連結填進 `public/config.js` 的 `BYBIT_INVITE_URL`、`BINGX_INVITE_URL`。

常見錯誤：
- Bybit `10003` Key 不對、`10004` 簽名錯（Secret 貼錯或多了空白）、`10005` 權限不對（沒勾「代理商」）、`10010` IP 不在白名單。
- BingX `100001` 簽名錯、`100419` IP 不在白名單。
- 「Bybit 擋下了這個地區的連線」：請求從美國或中國大陸發出。排程要用第 4 步的 Supabase，不要用 GitHub Actions。

## 7. Discord 審核機器人（選用）

研究員在 Discord 按「報名培訓計畫」→ 機器人開一個只有他和管理員看得到的報名頻道 → 在裡面選交易所、填 UID。Bybit、BingX 由機器人直接問交易所（用第 6 節的 API Key）是不是 CCC 邀請的，是就自動給身分組和一組他專用的實驗室密碼；OKX、UM 由管理員在他的報名頻道按「通過」才給。

1. 到 https://discord.com/developers/applications → **New Application**，名字例如「CCC 實驗室小幫手」。
2. **General Information** 頁：
   - 複製 **Application ID** 和 **Public Key**。
   - **Interactions Endpoint URL** 先空著（第 5 步再填）。
3. **Bot** 頁：按 **Reset Token** 複製 Token（只顯示一次）。下面的 Privileged Gateway Intents 都不用開。
4. Cloudflare Pages → Environment variables（Production），都選 **Encrypt**，然後 **Retry deployment**：
   - `DISCORD_APP_ID`：Application ID
   - `DISCORD_PUBLIC_KEY`：Public Key
   - `DISCORD_BOT_TOKEN`：Bot Token
5. 回到 **General Information**，**Interactions Endpoint URL** 填 `https://ccc-community-site.pages.dev/api/discord/interactions` → Save。Discord 會馬上測試一次，存得起來就代表網站接上了（存不起來通常是第 4 步還沒 Retry deployment）。
6. 網站後台 → **Discord 審核** → 按 **把機器人加進伺服器**，選 CCC 的伺服器 → 授權（權限已經帶好：管理頻道、管理身分組、傳送訊息）。
7. 回到後台按 **一鍵建立 Discord 頻道**。機器人會建立：
   - 分類「🧪 CCC 交易實驗室」
   - 「📝報名培訓計畫」：大家看得到、不能發言，放好報名按鈕
   - 「🔒報名審核」：只有管理員（和客服身分組）看得到，有人等審核時通知在這裡
   - 「📢研究員專屬公告」：只有實驗室身分組看得到，放公告（不放共用的實驗室密碼，每個人在自己的報名頻道拿到專用的一組）
   - 分類「🎫 培訓計畫報名」：每個人的私人報名頻道開在這裡，一般人看不到
   
   可以重複按：已經建好的不會重複建立，只會把權限調回正確；報名按鈕那則會更新成最新的文字，舊版預設的頻道名稱（例如「📝申請加入實驗室」「🔒申請審核」）會改成新的，你自己改過的名字不會動。
8. 如果結果寫「還差一步」：Discord 伺服器設定 → **身分組**，把機器人的身分組**拖到實驗室身分組上面**（機器人只能給比自己低的身分組）。
9. 用自己的小帳號按一次申請試試看。

頻道 ID、身分組、客服身分組、各交易所邀請連結可以在「進階設定」裡改。**邀請連結**填了會變成報名頻道下面的註冊按鈕（OKX 註冊、UM 開戶、Bybit 註冊、BingX 註冊），改了按「儲存設定」就會自動更新那則訊息。**客服身分組**：填了之後，這些身分組也看得到報名頻道、可以按通過（多個用逗號分開）；改了會自動更新申請分類和審核頻道的權限，之後開的報名頻道照新的設定。

審核：
- 「🔒報名審核」會通知有人在等，點裡面的頻道連結到他的報名頻道。審核訊息寫報名者、交易所、UID，到交易所代理後台確認是 CCC 邀請的，按「通過，給身分組」或「不通過」。有「管理身分組」權限或客服身分組的人才按得了。
- 結果直接寫在報名頻道裡；通過的會拿到一組只能用一次的實驗室密碼（也私訊一份，對方關掉私訊就只看得到頻道裡的）。
- 申請人或管理員按「關閉這個頻道」就會刪掉頻道。
- 同一個交易所 UID 只能通過一個人。後台「Discord 審核」頁可以看最近 30 筆申請。

常見問題：
- 審核頻道出現「給身分組失敗」：第 6 步沒勾 Manage Roles，或第 7 步機器人的身分組排在實驗室身分組下面。
- 「張貼失敗：機器人沒有這個頻道的權限」：機器人要能看到那個頻道、能傳訊息。
- 按按鈕顯示「此交互失敗」：第 5 步的網址沒存好，或 Cloudflare 的三個 DISCORD 設定有錯。

## 限制與建議

- **格式：** 上傳 **MP4（H.264 + AAC）** 最保險。MKV 或 HEVC 有些瀏覽器播不了，後台在上傳時會提醒。可以用 `ffmpeg -i in.mkv -c:v libx264 -c:a aac -movflags +faststart out.mp4` 轉檔。
- **大小：** 單一影片最大 5 GB。1 小時 1080p 錄影通常 1–3 GB。
- **連結期限：** 影片連結 1 小時後失效，播放中過期會自動換新連結並接著播。
- **防盜錄的極限：** 網頁擋不住螢幕錄影或手機翻拍。浮水印的用途是外流時看得出是哪個帳號。iPhone 的瀏覽器不支援把播放區整塊放大成全螢幕，所以 iPhone 上不顯示我們的全螢幕按鈕；但 iPhone 系統播放器自己的全螢幕擋不掉，用它全螢幕時浮水印不會出現。
- **免費額度：** R2 免費 10 GB，超過約每 GB 每月 0.015 美元。下載流量不收費。
