# 開發指南

## 本機跑網站

1. `npm install`
2. 把 `.dev.vars.example` 複製成 `.dev.vars`，填 Supabase、R2 的金鑰（這個檔案不會進 git）
3. `npm run dev`，打開 http://localhost:8788

會連到真的 Supabase 和 R2，小心不要刪到正式資料。只想看畫面或改功能，用下面的模擬伺服器比較安全。

## 自動測試

`npm test` 會：
1. 第一次自動在 `tests/` 安裝 Playwright（瀏覽器自動化）和字型，並用 ffmpeg 產生測試影片（`tests/fixtures/`）
2. 每一組測試都開一個乾淨的模擬伺服器（`tests/mock-server.mjs`，假的 Supabase、R2、API），用瀏覽器實際操作
3. 結果和截圖在 `tests/output/`

| 測試 | 內容 |
|---|---|
| `e2e.cjs` | 登入、列表、播放、上傳、實驗室密碼、研究員管理、手機版 |
| `v14.cjs` | 章節、筆記、寄信通知、觀看資格、觀看統計、封面 |
| `v15.cjs` | 交易量：填寫、貼上一整批、門檻、資格延長 |
| `v16.cjs` | 教學課程解鎖、使用教學、研究員稱呼 |
| `v17.cjs` | 提問回報、觀看分段、待跟進、網站狀況 |
| `v18.cjs` | BingX：綁定 UID、自動交易量、後台同步、手動存不蓋掉自動的數字 |
| `v20.cjs` | 後台「Discord 審核」頁：申請列表、機器人設定、張貼申請按鈕 |
| `v19.cjs` | Bybit：綁定 UID（主帳號）、同一個 UID 不能綁兩位、後台兩間的同步列 |

只跑某幾組：`npm test -- v16 v17`。

`tests/discord.mjs` 用假的 Supabase、Discord、BingX 把 Discord 審核機器人整個流程跑一遍（簽名、自動通過、人工審核、權限不夠），`npm test` 每次都會跑。

`tests/unit.mjs` 是不用瀏覽器的單元測試（資格一輪、課程解鎖週次、交易量達標、伺服器的小工具），`npm test` 每次都會先跑。改規則時先在這裡加一條。

**GitHub 自動測試**：`.github/workflows/test.yml`。每次開 PR、推到 `main` 都會自動跑 `npm test` 和 `npm run check`，結果在 PR 頁面下方（綠勾才合併）。失敗時可以在那次執行的頁面下載 `test-output` 看紀錄。

**改了 API 要同時改 `tests/mock-server.mjs`**，模擬伺服器的回傳格式要跟 `server/` 一樣，測試才有意義。

## 程式架構

### 規則只寫一次：`public/assets/js/shared/rules.js`

觀看資格（達標日起一個月）、交易量門檻、教學課程解鎖順序、觀看分段每格幾秒，都只寫在這一個檔案。前台、後台、伺服器（`server/lib/`）、測試用的假伺服器都讀它，改一次就全部一致。改了規則要一起更新 `docs/功能說明.md` 和 `PRODUCT.md`。

### 網頁（`public/`）

原生 HTML／CSS／JS，沒有框架、不用打包。`index.html`、`admin.html` 各載入一支進入點（`<script type="module">`），其他檔案用 `import` 接起來。

```
public/assets/
  app.css              只放載入順序；樣式在 css/ 各檔（順序會影響覆蓋，不要調換）
  css/                 base（顏色字型）、controls、header、list、watch、login、admin、dialogs、account、motion、responsive、course、feedback
  js/core/             前台後台共用：config（Supabase）、api（呼叫 /api、自動回報錯誤）、dom（el、$、圖示）、format、ui（toast、modal）、
                       version（新版本提示、更新公告）、tutorial（使用教學影片）、cjk（中文換行）、flap（左上角翻牌）；index.js 一次匯出
  js/shared/rules.js   規則（見上面）
  js/member/           研究員頁：main.js 進入點和網址分頁
                       list（直播留檔列表）、watch（播放頁）、chapters、notes、course（教學課程）、feedback（提問）、
                       auth（登入註冊）、menu（右上角選單）、account（資格提醒、本月交易量）、views（切換畫面）、state（共用狀態）
  js/admin/            後台：main.js 進入點和側欄分頁
                       videos（列表）、editor（編輯影片）、upload（上傳）、transfer（直傳 R2 的工具）、invites（實驗室密碼）、
                       members（研究員、資格）、volumes（交易量）、stats（觀看統計、觀看分段）、feedback、followup（待跟進）、health（網站狀況）
```

- 想改某個畫面，先看 `main.js` 開頭的對照表，找到對應的檔案。
- 共用狀態（目前登入的人、影片列表、正在看的影片）放在各自的 `state.js`，不要用全域變數。
- 切換研究員頁的分頁用 `views.js` 的 `showPage()`；離開播放頁會自動存進度（`onLeavePage`）。
- `window.App` 還在，給瀏覽器主控台除錯和測試用；程式裡請用 `import`。

### API（`functions/` → `server/`）

- `functions/api/[[path]].js` 依路徑找到 `server/` 裡對應的檔案（`server/admin/` 是後台用的）。每個檔案用 `route({ GET, POST, ... })` 寫，權限用 `requireMember`／`requireAdmin`。新增 API 要在這裡登記路徑。
- 共用工具在 `server/lib/`，一律從 `server/lib/index.js` 匯入：env（環境變數、Supabase）、auth（登入、權限）、r2（簽名網址）、dates（台灣日期）、mail（Brevo 寄信）、volume（`saveVolumes()`：手動填和自動同步共用的存檔＋延長資格）、bingx／bybit（交易所代理商 API：簽名、確認邀請關係、交易量）、bingx-sync／bybit-sync（同步一個月的交易量）、autosync（自動同步的交易所登記在 `PROVIDERS`，`syncAll()`、`syncExchange()`、後台狀態）、course、buckets、text（整理輸入）、random、http（route、readBody）。
- 資料庫只用 service role 從後端存取（所有表都開了 RLS 但沒有 policy），前端拿不到資料庫。
- 需要掃過大量觀看紀錄的統計（後台「觀看統計」「待跟進」）在資料庫裡算：`admin_video_stats()`、`admin_member_progress()`（在 `supabase/schema.sql`），伺服器用 `supabaseAdmin.rpc()` 呼叫。新增這類函式要 `revoke` 掉 anon、authenticated 的執行權限。
- 影片和檔案：後端簽 R2 的上傳／下載網址（`server/sigv4.js`），瀏覽器直接傳到 R2。
- 台灣時間：日期一律用 `todayTW()` 這類工具，伺服器在 UTC。
- 自動同步交易量（Bybit、BingX）：研究員綁定在 `server/exchange-link.js`（表 `exchange_links`），後台狀態和「立即同步」在 `server/admin/sync.js`。每天的排程是 Supabase 的 pg_cron（東京）用 pg_net 帶 `X-Cron-Secret` 打 `server/cron/sync.js`（設定在 `supabase/schema.sql` v1.9）；不要改回 GitHub Actions，Bybit 會擋美國 IP。要加新的交易所：寫 `server/lib/<交易所>.js` 和 `-sync.js`，登記到 `autosync.js` 的 `PROVIDERS`，再加進 `rules.js` 的 `AUTO_EXCHANGES`。本機測試可以用 `BINGX_BASE_URL`、`BYBIT_BASE_URL` 指到假的交易所（見 `tests/unit.mjs`）。
- Discord 審核機器人：用 Discord 的 HTTP 互動（不用另外開主機），入口 `server/discord/interactions.js`（`/api/discord/interactions`），先驗 Ed25519 簽名，3 秒內回應；要問交易所的先回「處理中」，用 `req.waitUntil()` 在背景做完再改訊息。訊息長相（按鈕、選單、表單、審核訊息）在 `server/lib/discord-flow.js`，Discord API 和設定在 `server/lib/discord.js`，後台在 `server/admin/discord.js`（設定存在 settings 的 `discord`，申請記在表 `discord_applications`）。本機測試可以用 `DISCORD_API_BASE` 指到假的 Discord（見 `tests/discord.mjs`）。
- 安全標頭（CSP 等）在 `public/_headers`。

## 寫法慣例

- 介面文字一律繁體中文、白話。成員叫「研究員」（或「實驗室研究員」），註冊碼叫「實驗室密碼」。
- 畫面照 `DESIGN.md`：固定深色、琥珀色數字、紅＝新、綠＝看完、橘＝警示。
- 金鑰只放在 Cloudflare 環境變數或 `.dev.vars`，不要寫進程式或 git。
